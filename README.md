# Taxi GO

Приложение заказа такси для Android и iOS: React Native + TypeScript, сервер NestJS, PostgreSQL и Socket.IO. Интерфейс основан на 10 изображениях из `designe/` и собран из нативных компонентов. Оплата наличными, валюта — кыргызский сом.

План работ находится в [PLAN.md](PLAN.md). Условия интеграции карт и нативной сборки — в [docs/MAPKIT.md](docs/MAPKIT.md). Фактические результаты проверки фиксируются в [docs/VERIFICATION.md](docs/VERIFICATION.md).

## Структура

```text
designe/             исходные макеты
mobile/              приложение клиента и водителя
server/              API, события, миграции и тестовые данные
docs/                интеграции и результаты проверки
scripts/             инструменты локального запуска
docker-compose.yml   PostgreSQL и сервер
```

## Возможности

- Вход по телефону, SMS-код, сохранение и обновление сессии, выход.
- Клиент: адреса и карта, серверная котировка, тариф, комментарий, заказ, состояния поездки, чат, звонок и оценка.
- Водитель: подтверждённый профиль, выход на линию, предложения заказов, принятие/пропуск, последовательные действия по поездке.
- История, профиль, настройки и депозит водителя с историей операций; наличный доход учитывается отдельно.
- REST и Socket.IO с проверкой прав. Назначение одного водителя и финансовые изменения защищены транзакциями и ограничениями PostgreSQL.

Статусы: `SEARCHING → ASSIGNED → ARRIVED → IN_PROGRESS → COMPLETED`, дополнительно `CANCELLED` и `NO_DRIVER`. Отмена водителем до начала возвращает заказ в поиск; «Я выхожу» только уведомляет водителя.

## Требования

- Node.js 22.13+ и npm.
- PostgreSQL 17+ или Docker Desktop с работающим Linux engine.
- Для Android: Android Studio, Android SDK и JDK 17.
- Для iOS: macOS, Xcode и CocoaPods. Windows не выполняет сборку iOS.
- Бесплатный ключ Yandex Mobile SDK MapKit для карты и маршрута A → B; до 1 000 пользователей карты в сутки при соблюдении условий Яндекса.

Это приложение использует нативный MapKit: необходим development build; Expo Go его не содержит.

В текущей рабочей папке уже собран Android APK: `mobile/android/app/build/outputs/apk/debug/app-debug.apk`. Это сборка для разработки, которой нужны запущенные Metro и API. Результаты её запуска и проверок — в [отчёте](docs/VERIFICATION.md).

## Быстрый локальный запуск сервера

Из корня проекта:

```powershell
Copy-Item .env.example .env
Copy-Item server/.env.example server/.env
npm --prefix server ci
```

В `.env` замените пароль базы. В `server/.env` укажите тот же пароль в `DATABASE_URL`, а также разные случайные значения `JWT_SECRET` и `OTP_SECRET` длиной не менее 32 символов. Пример генерации одного значения:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

```powershell
docker compose up -d db
npm --prefix server run db:migrate
npm --prefix server run db:seed
npm --prefix server run dev
```

API: `http://localhost:3000/api`. Документация Swagger: `http://localhost:3000/api/docs`. Описание запросов и событий: [server/API.md](server/API.md).

Тестовые данные создаются явно командой `db:seed`; не запускайте её на рабочей базе.

| Роль | Телефон | Код в development |
|---|---|---|
| Клиент | +996700123456 | 123456 |
| Водитель 1 | +996700111111 | 123456 |
| Водитель 2 | +996700222222 | 123456 |
| Администратор | +996700999999 | 123456 |

Водители получают подтверждённые тестовые профили и начальный депозит. Пользователь не может сам назначить себе роль водителя или администратора через приложение.

### Если Docker недоступен

Предусмотрен необязательный локальный PostgreSQL для разработки. Он сохраняет данные в `.local/`, слушает только `127.0.0.1:55432` и не устанавливает системную службу.

```powershell
npm ci
npm run db:local
```

Оставьте процесс работающим. В другом терминале выполните `npm run setup:local`: будут созданы локальные `.env` с адресом базы и случайными секретами (существующие файлы сохраняются). Если `server/.env` уже существует, возьмите `DATABASE_URL` из `.local/database.env` и укажите его вручную. Затем выполните миграции, seed и запуск сервера, как выше. `.local/` и файлы `.env` исключены из Git.

## Запуск приложения

```powershell
Copy-Item mobile/.env.example mobile/.env
npm --prefix mobile ci
```

Укажите в `mobile/.env` адрес API и ключ MapKit. Для Android Emulator сервер на компьютере доступен через `http://10.0.2.2:3000/api`. Для физического телефона используйте LAN-адрес компьютера, например `http://192.168.1.10:3000/api`; оба устройства должны находиться в одной сети. В production используйте HTTPS.

```powershell
cd mobile
npx expo prebuild --platform android
npm run android
```

На Mac для iOS:

```sh
cd mobile
npm ci
npx expo prebuild --platform ios
npm run ios
```

Разрешите геолокацию и уведомления. Геолокация нужна клиенту только для кнопки «Моё местоположение» и работает при открытом приложении. Фоновый доступ не запрашивается. Детали ключа и лимита — в `docs/MAPKIT.md`.

## Настройка внешних сервисов

Полный список переменных находится в `server/.env.example` и `mobile/.env.example`.

- **SMS:** production требует реальный шлюз; тестовый код допускается только при `NODE_ENV=development` и включённом `DEV_AUTH_ENABLED`.
- **Маршрут и стоимость:** MapKit показывает маршрут A → B внутри приложения. Сервер при `ROUTING_PROVIDER=approximation` самостоятельно рассчитывает приблизительную контрольную дистанцию и фиксирует цену; клиентская цена не принимается. Точный серверный Router API можно подключить позднее отдельным ключом.
- **Карты:** бесплатный ключ MapKit ограничьте идентификаторами приложений. Машины на карте не отслеживаются, фоновая геолокация водителя отключена. Следите за лимитом 1 000 DAU и актуальными условиями Яндекса.
- **Push:** требуется настройка провайдера, а также APNs/FCM для сборок устройств. Наличие кода регистрации не означает, что push работает без настройки учётных данных.
- **Поддержка:** задайте действующий телефон своей службы поддержки в `SUPPORT_PHONE`.

## Проверки

```powershell
npm --prefix server run build
npm --prefix server test
npm --prefix mobile run typecheck
npm --prefix mobile run test:native
npm --prefix mobile run test:api
npm --prefix mobile run test:ui
```

Интеграционные тесты используют отдельную PostgreSQL-базу. Установите `DATABASE_URL` в адрес **тестовой** базы и `TEST_DATABASE_RESET=true`, примените миграции, затем запустите `npm --prefix server run test:integration`. Тесты удаляют данные в указанной базе. Не направляйте их в рабочую базу.

При использовании локального PostgreSQL можно выполнить `npm run test:local`: команда сама выбирает только локальную базу `taxi_test`, применяет миграции и запускает сборку и серверные тесты.

На Windows перед `npm run build` и `npm run test:local` остановите запущенный API: Prisma не может заменить DLL клиента, пока она используется другим процессом. Для изменения исходников при работающем `npm run dev` запустите `npm --prefix server run watch` во втором терминале.

Сценарий испытания на двух устройствах и границы локальной проверки перечислены в `docs/VERIFICATION.md`.

## Перед рабочим запуском

Подключите реальные SMS, бесплатный ключ MapKit и push; примите условия MapKit в кабинете, настройте HTTPS и резервное копирование PostgreSQL. Уберите development-провайдеры SMS/push. Проверьте Android и iOS на физических устройствах, включая потерю сети и восстановление сессии. Фактический статус сборок и испытаний смотрите в отчёте проверки, а не выводите из наличия исходников.

## Railway

Репозиторий содержит `Dockerfile.railway` и `railway.json`. Для API создайте сервис из корня репозитория, подключите PostgreSQL и задайте `DATABASE_URL=${{Postgres.DATABASE_URL}}`. Миграции выполняются автоматически перед запуском, а Railway проверяет `/api/health`. Секреты и ключи задаются только в Railway Variables.

Текущий демонстрационный API опубликован по адресу `https://api-production-3839.up.railway.app/api`. В `mobile/.env.example` уже указан этот адрес. Пока не подключён настоящий SMS-шлюз, Railway использует development-вход с кодом `123456`; перед рабочим запуском его необходимо отключить.
