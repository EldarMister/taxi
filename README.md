# Atlas

Приложение заказа такси, автомобильной доставки, грузоперевозок и доставки еды для Android и iOS: React Native + TypeScript, сервер NestJS, PostgreSQL и Socket.IO. Интерфейс собран из нативных компонентов по референсам из `designe/`, включая семь экранов доставки из `designe/еда/`. Оплата наличными, валюта — кыргызский сом.

План работ находится в [PLAN.md](PLAN.md). Условия интеграции карт и нативной сборки — в [docs/MAPKIT.md](docs/MAPKIT.md). Фактические результаты проверки фиксируются в [docs/VERIFICATION.md](docs/VERIFICATION.md).

## Структура

```text
designe/             исходные макеты
mobile/              отдельные client/driver сборки из общего мобильного кода
server/              API, события, миграции и тестовые данные
docs/                интеграции и результаты проверки
scripts/             инструменты локального запуска
admin/               веб-панель управления сервисом
docker-compose.yml   PostgreSQL и сервер
```

## Возможности

- Два отдельных приложения из общего кода: Atlas для пассажира и Atlas pro для водителя. У них разные идентификаторы, роли аккаунтов и настройки сборки; они устанавливаются рядом. [Сборки и варианты](docs/APP-VARIANTS.md).
- Вход по номеру телефона и SMS-коду, сохранение и обновление сессии, выход; после входа приложение проверяет соответствие роли установленной версии. Русский и кыргызский интерфейс, светлая и тёмная темы, настройки уведомлений, профиль и фото водителя. [Экран входа](docs/AUTH-UI.md).

### Такси для пассажира

- Большая карта Atlas на данных OpenStreetMap, GPS для начальной точки, ручной выбор адреса, поиск адресов и подтверждение точки на карте. Две точки маршрута, автомобильный маршрут и предварительная стоимость по выбранному тарифу.
- Горизонтальный выбор тарифов с рассчитанной ценой, отдельные поля подъезда и пожеланий, заказ поездки для себя или другого пассажира с его именем и телефоном. Цена рассчитывается на сервере и фиксируется при оформлении; оплата поездки — наличными в сомах.
- Поиск водителя, экран назначенной поездки, прибытие, начало и завершение. Можно отменить поездку до её начала, позвонить водителю, переписываться в чате и сообщить «Я выхожу» после его прибытия.
- После назначения карта показывает только своего водителя и его актуальное движение; маршрут подъезда и этапы поездки обновляются через Socket.IO. При потере связи состояние восстанавливается с сервера. После поездки — оценка водителя и история поездок с деталями маршрута.

### Atlas pro для водителя

- Новый номер может зарегистрироваться прямо в Atlas pro после SMS-входа: имя, фамилия, марка и госномер машины, обязательное фото автомобиля и необязательное фото профиля. Заявка остаётся неподтверждённой до проверки администратором; водитель не может самостоятельно назначить себе класс машины.
- Администратор назначает автомобилю класс `Эконом`, `Комфорт` или `Грузовой`. Водитель Эконом не может включить Комфорт, водитель Комфорт может отдельно включать и выключать Эконом, а грузовой водитель получает только грузовые заказы.
- В настройках водитель легковой машины может одновременно включить поездки такси и доставку небольших чистых грузов либо оставить только один вид работы. Грузовой водитель отдельно управляет приёмом крупных грузов. Выключить сразу все виды заказов нельзя.
- Подтверждение водителя и автомобиля администратором, профиль с рейтингом, переход «На линии»/«Не на линии». Для выхода на линию нужны GPS, подтверждённый автомобиль, хотя бы один включённый вид заказов и достаточный депозит.
- Заказ получает по очереди один водитель со свежей GPS-точкой. Сначала рассматриваются ближайшие к точке подачи; если несколько водителей находятся в пределах 250 м от ближайшего, приоритет у более высокого среднего рейтинга. Расстояние для выбора считается по прямой. На принятие предложения даётся 30 секунд. Пропуск или истечение срока передаёт заказ следующему подходящему водителю; пропущенный заказ этому водителю повторно не приходит.
- Карточка предложения с маршрутом, ценой, комментарием и обратным отсчётом; принятие и пропуск, звуковое и push-уведомление при настроенном провайдере. Одновременно можно вести только одну активную поездку.
- Маршрут до пассажира и до пункта назначения, GPS-навигация, русские голосовые подсказки, этапы «Приехал → Начать → Завершить», звонок и чат. Доступна отдельная настройка фоновой навигации активной поездки при системном разрешении. [Навигация и трекинг](docs/DRIVER-TRACKING.md).
- Водитель может отменить принятую поездку до её начала: заказ вернётся в поиск для других водителей. После завершения комиссия единожды списывается из депозита, наличная выручка учитывается отдельно. Доступны история поездок, операции и баланс, оценка пассажира.

### Доставка и грузовой

- Карточка «Грузовой» активна на главном экране и открывает отдельный экран доставки поверх карты, без поля «Куда едем?». Адрес отправки автоматически заполняется текущим местоположением, его можно изменить; ниже указывается адрес назначения.
- Два вида заказа: `Доставка` на легковой машине для небольших грузов, которые не пачкают салон, и `Грузовой` для крупного груза. Тарифы, минимальная цена и комиссия каждого вида настраиваются администратором.
- Нижнюю карточку можно потянуть вверх или открыть кнопкой параметров. В подробной панели указываются описание груза, доставка от двери до двери и комментарий. Для грузовой машины дополнительно доступны тип кузова, 0–2 грузчика и запланированная подача.
- Маршрут, расстояние, время и стоимость рассчитываются сервером так же, как для такси. Цена фиксируется при оформлении. Доставка проходит по общим этапам поиска, назначения, прибытия, выполнения и завершения; доступны карта, звонок, чат, история и оценки.
- Доставка предлагается только водителям, которые находятся на линии, имеют свежую GPS-точку, подходящий назначенный класс и включили этот вид работы. Легковая доставка никогда не попадёт грузовой машине, а грузовой заказ — водителю Эконом или Комфорт.
- Интерфейс курьера на мото отмечен как будущая возможность и пока не создаёт заказов.

### Доставка еды

- Главный экран с выбором такси или еды; каталог ресторанов, поиск, фильтры кухни, избранное, категории меню, карточки блюд, дополнения и сохраняемая корзина.
- Доставка или самовывоз, комментарий, наличная оплата, оформление без дублей при повторе запроса, активный заказ и история. Статусы заказа обновляются с сервера. Меню, цены и состав уже оформленного заказа сохраняются в истории. [Возможности и API доставки](docs/FOOD-API.md).

### Управление сервисом

- [Веб-панель администратора](docs/ADMIN.md) с отдельным входом: обзор и поиск заказов такси, автомобильной/грузовой доставки и еды, фильтры и история, отмены и ручная смена статусов заказа еды.
- Проверка новых заявок Atlas pro, просмотр фото машины, назначение класса Эконом/Комфорт/Грузовой, подтверждение и редактирование водителей и машин, пополнение депозита и финансовые операции. Тарифы разделены по виду заказа и необходимому классу автомобиля. Также доступны рестораны, меню, категории, блюда, дополнения, фотографии, баннеры и журнал действий с проверкой прав.
- Сервер защищает роли и данные участников, отправляет события через Socket.IO и push, сохраняет заказы в PostgreSQL. Принятие поездки и списание комиссии защищены от повторов и одновременных действий.

Статусы: `SEARCHING → ASSIGNED → ARRIVED → IN_PROGRESS → COMPLETED`, дополнительно `CANCELLED` и `NO_DRIVER`. Отмена водителем до начала возвращает заказ в поиск; «Я выхожу» только уведомляет водителя.

Для определения ближайшего водителя приложение Atlas pro должно быть открыто и передавать свежую GPS-точку, пока водитель на линии. После 30 секунд без новой точки водитель временно исключается из выдачи. Координаты других водителей пассажиру не показываются. Если подходящих водителей нет, заказ получает статус `NO_DRIVER`. Автоматическое назначение курьеров доставки еды и онлайн-оплата пока не подключены. Новая логика выдачи работает после миграции сервера и установки обновлённой сборки водителя; ранее собранные APK её не содержат.

## Требования

- Node.js 22.13+ и npm.
- PostgreSQL 17+ или Docker Desktop с работающим Linux engine.
- Для Android: Android Studio, Android SDK и JDK 17.
- Для iOS: macOS, Xcode и CocoaPods. Windows не выполняет сборку iOS.
- Настроенные OSM-тайлы, OSRM для автомобильных маршрутов и Nominatim для адресов. Для рабочего сервиса нужны собственные экземпляры или подходящие поставщики; публичные демонстрационные серверы не гарантируют доступность.

Это приложение использует нативный MapLibre: необходим development build; Expo Go его не содержит. Ключи Яндекса не требуются.

Предыдущая сборка для телефона хранится в [Taxi-GO-android-arm64.apk](artifacts/Taxi-GO-android-arm64.apk) и использует публичный HTTPS API. Она выпущена до перехода на OSM: для новой карты и навигации пересоберите и установите клиентское и водительское приложения. Состояние проверки прежнего APK и подключения — в [docs/CONNECTIVITY.md](docs/CONNECTIVITY.md).

Предыдущая локальная сборка доставки сохранена: [Taxi-GO-food-local.apk](artifacts/Taxi-GO-food-local.apk). Встроенный адрес API — `http://10.0.2.2:3000/api`; она предназначена только для Android Emulator с запущенным локальным сервером.

Прежняя сборка для разработки сохранена: [app-debug.apk](mobile/android/app/build/outputs/apk/debug/app-debug.apk). Ей нужны запущенные Metro и API. Результаты её запуска и проверок — в [отчёте](docs/VERIFICATION.md).

## Быстрый локальный запуск сервера

Из корня проекта:

```powershell
Copy-Item .env.example .env
Copy-Item server/.env.example server/.env
npm --prefix server ci
```

В `.env` замените пароль базы. В `server/.env` укажите тот же пароль в `DATABASE_URL`, а также разные случайные значения `JWT_SECRET` и `OTP_SECRET` длиной не менее 32 символов. Пример генерации одного значения:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

```powershell
docker compose up -d db
npm --prefix server run db:migrate
npm --prefix server run db:seed
npm --prefix server run dev
```

API: `http://localhost:3000/api`. Документация Swagger: `http://localhost:3000/api/docs`. Описание запросов и событий: [server/API.md](server/API.md).

Тестовые данные создаются явно командой `db:seed`; не запускайте её на рабочей базе.

| Роль | Телефон | Код в development |
|---|---|---|
| Клиент | +996700123456 | 123456 |
| Водитель 1 | +996700111111 | 123456 |
| Водитель 2 | +996700222222 | 123456 |

Водители из тестовых данных получают подтверждённые профили и начальный депозит. Новый пользователь Atlas pro может отправить заявку водителя, но не может сам подтвердить её, назначить класс Комфорт/Грузовой или стать администратором.

Административный вход через SMS запрещён, в том числе для тестового аккаунта из seed. Настройка владельца, адрес панели и локальный файл доступа описаны в [docs/ADMIN.md](docs/ADMIN.md).

### Если Docker недоступен

Предусмотрен необязательный локальный PostgreSQL для разработки. Он сохраняет данные в `.local/`, слушает только `127.0.0.1:55432` и не устанавливает системную службу.

```powershell
npm ci
npm run db:local
```

Оставьте процесс работающим. В другом терминале выполните `npm run setup:local`: будут созданы локальные `.env` с адресом базы и случайными секретами (существующие файлы сохраняются). Если `server/.env` уже существует, возьмите `DATABASE_URL` из `.local/database.env` и укажите его вручную. Затем выполните миграции, seed и запуск сервера, как выше. `.local/` и файлы `.env` исключены из Git.

## Запуск приложения

```powershell
Copy-Item mobile/.env.example mobile/.env
npm --prefix mobile ci
```

Укажите в `mobile/.env` адрес API; векторный стиль карты включён по умолчанию. Свой стиль можно задать через `EXPO_PUBLIC_MAP_STYLE_URL`, резервные растровые тайлы — через `EXPO_PUBLIC_OSM_TILE_URL`. В `server/.env` настройте `OSRM_BASE_URL` и `NOMINATIM_BASE_URL`. По умолчанию приложение подключается к демонстрационному API Railway по HTTPS, в том числе при отсутствии `.env`. Если вы запускаете собственный локальный сервер, для Android Emulator используйте `http://10.0.2.2:3000/api`, для физического телефона — LAN-адрес компьютера, например `http://192.168.1.10:3000/api`; оба устройства должны находиться в одной сети. Для такого локального запуска установите `APP_ENV=development`. В production используйте HTTPS.

Адрес API включается в приложение во время сборки. После изменения `EXPO_PUBLIC_API_URL` перезапустите Metro для development build или соберите и установите новый APK для автономной сборки. Изменение `.env` не меняет уже установленный APK. Production-конфигурация останавливает сборку при URL-заглушке, HTTP или адресе localhost/эмулятора. Подробности диагностики подключения — в [docs/CONNECTIVITY.md](docs/CONNECTIVITY.md).

```powershell
cd mobile
npx expo prebuild --platform android
npm run android
```

На Mac для iOS:

```sh
cd mobile
npm ci
npx expo prebuild --platform ios
npm run ios
```

Разрешите геолокацию и уведомления. Клиент использует GPS для выбора адреса, водитель — также для собственного положения и навигации. При активном ведении экран остаётся включённым; сворачивание останавливает маршрутные подсказки и наблюдение GPS. Фоновый доступ не запрашивается. Настройка сервисов и ограничения описаны в [docs/MAPKIT.md](docs/MAPKIT.md).

## Настройка внешних сервисов

Полный список переменных находится в `server/.env.example` и `mobile/.env.example`.

- **SMS:** production требует реальный шлюз; тестовый код допускается только при `NODE_ENV=development` и включённом `DEV_AUTH_ENABLED`.
- **Маршрут и стоимость:** `ROUTING_PROVIDER=osrm`, `OSRM_BASE_URL` — автомобильный маршрут, дорожная дистанция для серверного тарифа и шаги навигации. Клиентская цена не принимается. Текущие пробки OSRM сам по себе не учитывает.
- **Карты и адреса:** встроенный векторный стиль Atlas использует данные OpenMapTiles/OpenStreetMap; `EXPO_PUBLIC_MAP_STYLE_URL` меняет стиль, `EXPO_PUBLIC_OSM_TILE_URL` задаёт только резервные тайлы. `NOMINATIM_BASE_URL` — поиск и обратное геокодирование на сервере. Сохраняйте атрибуцию и настройте сервисы под нагрузку. Для собственных OSRM/Nominatim на данных Кыргызстана есть [инструкция запуска](server/MAPS.md) и `docker-compose.maps.yml`. Публичный Nominatim не подходит для рабочего сервиса такси; подробности и первичные источники — в [docs/MAPKIT.md](docs/MAPKIT.md).
- **Push:** требуется настройка провайдера, а также APNs/FCM для сборок устройств. Наличие кода регистрации не означает, что push работает без настройки учётных данных. Полная схема событий и список переменных: [docs/PUSH.md](docs/PUSH.md).
- **Поддержка:** задайте действующий телефон своей службы поддержки в `SUPPORT_PHONE`.

## Проверки

```powershell
npm --prefix server run build
npm --prefix server test
npm --prefix mobile run typecheck
npm --prefix mobile run test:native
npm --prefix mobile run test:navigation
npm --prefix mobile run test:variant
npm --prefix mobile run test:api
npm --prefix mobile run test:auth
npm --prefix mobile run test:booking
npm --prefix mobile run test:food
npm --prefix mobile run test:ui
```

Интеграционные тесты используют отдельную PostgreSQL-базу. Установите `DATABASE_URL` в адрес **тестовой** базы и `TEST_DATABASE_RESET=true`, примените миграции, затем запустите `npm --prefix server run test:integration`. Тесты удаляют данные в указанной базе. Не направляйте их в рабочую базу.

При использовании локального PostgreSQL можно выполнить `npm run test:local`: команда сама выбирает только локальную базу `taxi_test`, применяет миграции и запускает сборку и серверные тесты.

На Windows перед `npm run build` и `npm run test:local` остановите запущенный API: Prisma не может заменить DLL клиента, пока она используется другим процессом. Для изменения исходников при работающем `npm run dev` запустите `npm --prefix server run watch` во втором терминале.

Сценарий испытания на двух устройствах и границы локальной проверки перечислены в `docs/VERIFICATION.md`.

## Перед рабочим запуском

Подключите реальные SMS и push, настройте собственные или предоставленные поставщиком OSM-тайлы, OSRM и Nominatim, HTTPS и резервное копирование PostgreSQL. Уберите development-провайдеры SMS/push. Проверьте Android и iOS на физических устройствах, включая русскую озвучку навигации, потерю GPS и сети, возврат из фона и восстановление сессии. Фактический статус сборок и испытаний смотрите в отчёте проверки, а не выводите из наличия исходников.

## Railway

Репозиторий содержит `Dockerfile.railway` и `railway.json`. Для API создайте сервис из корня репозитория, подключите PostgreSQL и задайте `DATABASE_URL=${{Postgres.DATABASE_URL}}`. Миграции выполняются автоматически перед запуском, а Railway проверяет `/api/health`. Секреты и ключи задаются только в Railway Variables.

Текущий демонстрационный API опубликован по адресу `https://api-production-47be.up.railway.app/api`. В `mobile/.env.example` уже указан этот адрес. Пока не подключён настоящий SMS-шлюз, Railway использует development-вход с кодом `123456`; перед рабочим запуском его необходимо отключить.

Обновление API с доставкой, каталогом, баннерами и административными маршрутами развёрнуто успешно. Панель размещается вместе с API на Railway: [api-production-47be.up.railway.app/admin/](https://api-production-47be.up.railway.app/admin/). Доступ владельца сохранён в `.local/admin-access.txt`. Четыре ресторана из референсов остаются демонстрационными. Сведения о проверке и резервной копии — в [docs/ADMIN.md](docs/ADMIN.md).

Workflow нативных сборок использует тот же адрес; для собственного сервера задайте переменную GitHub Actions `EXPO_PUBLIC_API_URL` в настройках репозитория.
