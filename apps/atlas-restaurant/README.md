# Atlas Restaurant 2

Новое независимое приложение для владельцев и менеджеров ресторанов. React Native / Expo 54 / TypeScript; Android, iOS и web. Ветка разработки: `feature/atlas-restaurant-v2`.

## Запуск

Из корня репозитория:

```powershell
npm --prefix apps/atlas-restaurant ci
Copy-Item apps/atlas-restaurant/.env.example apps/atlas-restaurant/.env
npm --prefix apps/atlas-restaurant start
```

В `.env` задайте `EXPO_PUBLIC_API_URL` существующего Atlas API. Для Android Emulator локальный API — `http://10.0.2.2:3000/api`; для телефона — LAN-адрес компьютера. По умолчанию используется локальный API. Вход: реальная учётная запись владельца или менеджера, созданная через Atlas. Демонстрационного входа и встроенных тестовых ресторанов нет.

```powershell
npm --prefix apps/atlas-restaurant run web
npm --prefix apps/atlas-restaurant run android
```

Для iOS используйте `npm run ios` на macOS. Папки `android/` и `ios/` генерируются из `app.config.ts`, не являются источником конфигурации и исключены из Git.

## Проверки и независимая сборка

```powershell
npm --prefix apps/atlas-restaurant run typecheck
npm --prefix apps/atlas-restaurant test
npm --prefix apps/atlas-restaurant run build
```

`build` создаёт production JS/Hermes bundles и ресурсы трёх платформ в `apps/atlas-restaurant/dist`. Это не подписанные APK/IPA. `build:web` собирает только web. Сборка не требует установки зависимостей клиентского Atlas или сервера. Контрактные тесты читают исходные валидаторы сервера в этом репозитории, не подключаясь к рабочей базе.

Генерация нативного проекта выполняется явно, отдельно от сборки JS:

```powershell
cd apps/atlas-restaurant
npm run native:generate -- --platform android
```

Отдельный CI: `.github/workflows/restaurant-v2.yml`. Браузерные тесты: `scripts/verify-browser.cjs`, требуется Playwright (или `PLAYWRIGHT_MODULE` с путём установленного пакета), запущенный web на 8097 и локальный URL API. Они подменяют API **только внутри тестового браузера**, а не приложения.

Реальная интеграция с БД: `server/test/restaurant-v2.integration.test.ts`. Локальный runner `node server/test/run-restaurant-v2-local.cjs` допускает только `127.0.0.1:55432/taxi_test` из `.local/database.env`, мигрирует эту тестовую БД, использует собственные уникальные данные и удаляет только их. Сначала соберите сервер. Рабочая база, внешние маршрутизаторы, SMS и push в этой проверке не используются.

## Выпуск Android и iOS

Для установки на Android-телефон без Metro есть самостоятельная сборка с локальной тестовой подписью. Поддерживает ARM64/ARMv7 и Android 8.0 или новее; код Hermes и ресурсы встроены в APK. Из директории приложения:

```powershell
$env:EXPO_PUBLIC_API_URL='https://api-production-47be.up.railway.app/api'
npm run build:phone
```

Файл: `builds/Atlas-Restaurant-2.0.0-phone.apk`. Это установочный вариант для проверки на телефоне, с тестовым сертификатом; для публикации используйте исходные release credentials ниже. Если установленный APK подписан другим сертификатом, обновление поверх него Android не разрешит.

Идентификатор сохранён: `kg.taxigo.restaurant`, scheme `atlas-restaurant`. Версия 2.0.0, Android versionCode / iOS buildNumber 200. Для обновления ранее установленных APK необходима **та же подпись**, которой они подписаны.

Настройте реальный HTTPS `EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_RESTAURANT_EAS_PROJECT_ID` существующего Restaurant-проекта и его исходные signing credentials в EAS. Значения не включаются в Git. Из директории приложения:

```powershell
npx eas-cli build --platform android --profile apk
npx eas-cli build --platform android --profile production
npx eas-cli build --platform ios --profile production
```

Профили release задают `APP_ENV=production`; сборка отклонит отсутствующий, локальный или небезопасный API URL. Секретный серверный ключ в мобильном приложении не нужен.

Локальная release-сборка: задайте `APP_ENV=production` и реальный HTTPS `EXPO_PUBLIC_API_URL` до генерации Android, затем настройте `signingConfigs.release` (либо `atlasRelease`) и `buildTypes.release.signingConfig`, используя исходный keystore вне Git и свойства `ATLAS_RELEASE_*`. Затем `npm run build:apk`. Скрипт отказывается считать debug-подпись production-релизом. Нативные debug-сборки предназначены для проверки, не для публикации.

## Код

| Папка | Назначение |
|---|---|
| `src/app` | Вход, восстановление сессии, выбор ресторана, права, навигация, загрузка данных |
| `src/data` | HTTP-клиент, SecureStore, refresh, изоляция ответов, защита команд |
| `src/domain` | Собственные типы фактического ресторанного API |
| `src/ui` | Палитра Atlas, Inter, карточки, кнопки, sheets, skeleton, кешированные фото |
| `src/features/menu` | Категории, блюда, фотографии, модификаторы, клиентский предпросмотр |
| `src/features/orders` | Лента, уведомления в открытом приложении, статусы, два способа доставки |
| `src/features/management` | Dashboard, профиль, акции, команда, аналитика |
| `assets` | Сохранённые фотографии с источниками и иконка приложения |
| `tests` | Поведенческие и контрактные тесты без production-данных |

Frontend не импортирует код из `mobile/`, старого приложения или серверного runtime. Навигация, состояние, зависимости, lockfile и сборка принадлежат только этому приложению.

## Поведение и ограничения API

- Сохранение полного каталога отправляет `updatedAt`. Конфликт версии не перезаписывается автоматически; редактор предлагает загрузить актуальные данные.
- Любая команда привязана к ресторану и конкретному заказу. Повторные нажатия объединяются/блокируются. Неопределённый результат доставки сверяется с сервером перед повтором.
- Сессия native хранит только токены в SecureStore, мигрирует старый `session.v1`. Web хранит токены только в памяти и требует повторного входа после перезагрузки страницы.
- Уведомления и вибрация работают в активном приложении на всех вкладках. Polling — каждые 10 секунд, при ошибках до 30 секунд, немедленно при возвращении в приложение/восстановлении web-сети. Новые события сверяются с полным доступным снимком.
- Сервер возвращает последние 200 заказов. Лента и популярные блюда ограничены этим окном; аналитика использует отдельный API и выбранный период. События старше 200 заказов после длительного отключения нельзя гарантированно восстановить без пагинации/курсорного API.
- Категории поддерживают создание, название, порядок и удаление пустых категорий. Отдельного признака доступности категории нет. Расписания работы в API нет; используется `isOpen`.
- Фотографии: основное фото и обложка блюда/ресторана, обрезка, масштаб, замена, JPEG-оптимизация. Произвольную галерею сервер не хранит.
- Предпросмотр использует ту же цену карточки, что клиентский Atlas: лучшую активную процентную/фиксированную скидку без порога суммы, без суммирования акций и без скидки на добавки. Акции с минимальной суммой и бесплатная доставка рассчитываются в клиентской корзине; предпросмотр явно сообщает об этом. Окончательное применение акций остаётся на сервере.
- Только наличные. Фоновый push, онлайн-оплата и публикация отзывов не представлены как действующие функции.
- Анимации: короткое появление фото/новых заказов/изменившейся цены, native modal sheets, поддержка Reduce Motion. Переключение вкладок мгновенное.
- Проверка на физических Android/iOS устройствах и release-подпись остаются отдельными этапами выпуска.

Полный отчёт о реализации, API и выполненных проверках: `docs/ATLAS-RESTAURANT-V2.md` в корне репозитория.
