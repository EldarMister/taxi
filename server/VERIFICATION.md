# Проверка сервера — 5 сентября 2026

Проверено на Windows, Node.js 24.8.0, Prisma 6.19.0, настоящем PostgreSQL 18 (отдельная одноразовая база `taxi_test`). Эмуляция БД не использовалась.

- `npm run db:migrate`: начальная миграция успешно применена к demo и test БД, включая частичные уникальные индексы и SQL CHECK ограничения.
- `npm run build`: Prisma Client сгенерирован, TypeScript успешно собран. Последние изменения повторно собраны `tsc -p tsconfig.json`; повторная генерация неизменённого клиента при работающем Windows API ограничена блокировкой DLL операционной системой.
- `npm run db:seed`: тестовые клиент, два подтверждённых водителя, администратор, тарифы и депозиты созданы.
- `npm test`: 4/4 теста пройдены, без пропусков.
- `npm run test:eta`: 4/4 целевых теста времени подачи пройдены — маршрут водитель → клиент, общий запрос при конкурентном чтении, отсутствие подмены при ошибке провайдера, устаревшие точки, истечение 45-секундного кэша и ограничение его размера.
- `npm run test:integration`: последний прогон после добавления ETA — 8/8 пройден, без пропусков; продолжительность 72,14 секунды. Дополнительно проверены наличие ETA после назначения, неизменность цены и скрытие ETA/геометрии при устаревших координатах.

Интеграционные сценарии:

1. Валидация вложенного маршрута, отклонение цены клиента, запрет изменения роли и доступа клиента к административным операциям.
2. Пять одновременных повторов создания дают один заказ; конкурирующее принятие двух водителей даёт ровно одного победителя; чужой заказ и чат недоступны.
3. Один водитель не может одновременно получить заказы двух клиентов.
4. Отмена водителем возвращает заказ в поиск; отмена клиентом завершает его; новый водитель не получает переписку предыдущего назначения.
5. Полный путь ASSIGNED → ARRIVED → IN_PROGRESS → COMPLETED, уведомление «Я выхожу» без смены статуса, чат без дубликатов, Socket.IO-координаты только назначенному клиенту, переподключение и восстановление, пять повторов завершения с единственным списанием комиссии, отдельная наличная выручка, оценка.
6. Исключение устаревших и далёких координат, переход по таймауту в NO_DRIVER.
7. Пять параллельных пополнений с одним ключом создают ровно одно пополнение; изменение суммы с тем же ключом отклоняется.
8. Сохранение неверных SMS-попыток, блокировка кода, ограничение повторной отправки, ротация токенов, отзыв всей семьи при повторном использовании старого refresh-токена, отказ REST и Socket.IO после выхода.

Не проверялись реальная доставка SMS/push, коммерческие ключи Yandex, сборки iOS/Android и полный сценарий на физических устройствах. Для них нужны реквизиты провайдеров и устройства; серверные автоматические проверки их не заменяют. Эксплуатационные ограничения описаны в `API.md`.
