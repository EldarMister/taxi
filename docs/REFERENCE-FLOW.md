# Taxi GO — сверка сценариев с референсами

Актуальная переработка от 6 сентября 2026. Бело-синий клиент сверялся с живым Яндекс Go 5.91.2 и папкой `designe/дизайн к которому стремимс`. Водительская часть — с `новый заказ такси.png`, `профиль таксиста.png`, `история заказов таксиста.png`.

## Клиент

| Экран / действие | Поведение |
| --- | --- |
| Главный экран | Карта, неподвижная метка подачи, текущий адрес сверху, компактная панель «Такси / Куда едем?». |
| Движение стартовой карты | После остановки меняется подача и адрес. Дополнительное подтверждение не требуется. |
| «Куда едем?» | Панель двух адресов и недавних направлений из собственной истории. Клавиатура появляется при нажатии на поле. |
| «Карта» у активного адреса | Редактируется только выбранная точка. Карта движется под центральной меткой. Нет верхних вкладок «Откуда / Куда». |
| «Готово» на карте | Сохраняется выбранная точка, открывается основной экран. Если обе точки заданы — маршрут и тарифы. |
| «Назад» с карты | Несохранённая точка отменяется, возвращается прежний маршрут или стартовый экран. |
| Адреса / тарифы | Изменение точки пересчитывает цены. Переключение тарифа использует его актуальную котировку. |
| Детали тарифа | Нижняя панель по высоте содержимого: автомобиль, описание, комментарий и сразу кнопка заказа. Пустого растягивания и вертикальной прокрутки нет. |
| Подъезд / комментарий | Компактная панель над клавиатурой. «Готово» сохраняет, закрытие отменяет черновик. |

Питомец, пожелания и специальные возможности, другой пассажир, плашка «Такси» над тарифами и внешняя кнопка карт не возвращены. Подъезд и комментарий сохранены. Сервер по-прежнему поддерживает две точки и наличную оплату. Атрибуция Яндекса расположена в нижнем левом углу.

Главные панели заказа и водительских действий не прокручиваются. Адресная выдача и история поездок являются списками. Срок котировки и автоматическое обновление цены сохранены: обновление до истечения и после возвращения из фона, без заказа по просроченной цене.

## Водитель

- Шапка «Новые заказы» поверх карты, состояние «Онлайн / Офлайн», вкладки «На линии / История / Баланс / Профиль» в ожидании, истории и балансе. Предложение, поездка и профиль используют полную высоту экрана, как в приложенных референсах; переходы доступны через меню.
- Предложение: реальный срок поиска заказа, две точки, расстояние, время поездки, наличная стоимость, комментарий, «Принять / Пропустить».
- После принятия: контакт пассажира и последовательные действия «Приехал → Начать поездку → Завершить поездку». Отмена и завершение подтверждаются в нижней панели.
- Профиль: водитель, автомобиль, выход на линию, депозит, суммы наличных поездок, настройки и поддержка. Отступы уменьшены, чтобы основные карточки помещались на телефоне.
- История: периоды, наличный доход, выполненные поездки, расстояние, рейтинг водителя и компактные строки маршрутов.

Рейтинг пассажира, время подачи, доход после комиссии и вывод средств не выдумываются: текущий API этих данных или операций не предоставляет. Отображаемый «Баланс» — депозит для комиссии, наличные пассажир передаёт водителю.

## Проверка

TypeScript и 38 мобильных тестов проходят, включая поведение центральной метки, отсутствие обязательного подтверждения на старте, сохранение/отмену комментария, удалённые функции, срок котировки и последовательность водительских действий.

Android-проверка использует настоящий MapKit и локальный сервер с тестовыми заказами для безопасного прохождения водительской цепочки. Зафиксированы запросы `accept → arrive → start → complete`. Эти данные и локальный адрес сервера не предназначены для итогового APK. Реальные поездки не оформлялись, iOS не запускался.

Итоговый APK установлен на эмулятор и отдельно проверен с Railway при выключенном локальном сервере. Загружаются карта, история адресов и результаты поиска. На маршруте до «Азия молл» сервер вернул 121 сом для «Эконом» и 174 сом для «Комфорт». Это цены проверочного маршрута на момент проверки, не фиксированные тарифы. Подъезд «2» сохраняется. После движения карты в редакторе подачи и нажатия «Назад» восстанавливаются прежний адрес, пункт назначения и подъезд. Реальный заказ не отправлялся.

После холодного перезапуска эмулятора клавиатура открывается снизу при выборе поля. Панель подъезда и кнопка «Готово» остаются над клавиатурой. Детали тарифа проверены также при размере экрана 720 × 1280: комментарий и кнопка заказа помещаются без вертикальной прокрутки. Эмулятор возвращён к 720 × 1600.

Ранее описанный принудительный сценарий «Подать сюда → выбрать прибытие» отменён. Документы предыдущих итераций сохраняют историю проверки, а текущий сценарий описан здесь.

## Сборка Android

Файл для установки: `artifacts/Taxi-GO-reference-flow.apk`, 126 102 607 байт. ARM64 + x86_64, подпись APK v2. SHA-256: `3F8D9397D587B86903C037EC91BD1524635C648F348B4F8B3E0E0D904078C39B`.

Проверено содержимое скомпилированного пакета: адрес Railway и настроенный MapKit-ключ встроены, локальный адрес проверочного сервера отсутствует. Значение ключа не публикуется. Исправлена зависимость Gradle от переменных окружения и dotenv-файлов: смена API или ключа теперь обновляет JS-пакет, даже если исходники не менялись. До этого Gradle мог ошибочно считать пакет актуальным после смены окружения.
