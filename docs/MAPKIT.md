# OpenStreetMap, OSRM и навигация водителя

Atlas и Atlas pro используют общую карту OpenStreetMap через нативный MapLibre. Векторный стиль отдельно оформляет дороги, здания, парки и воду. Поверх недельной выгрузки OpenFreeMap источник Shortbread дополняет сеть дорог, контуры зданий, названия улиц, зелёные зоны, парковки, номера домов и организации. Подписи выбираются на русском или кыргызском языке приложения, если соответствующий тег имени есть в OSM. Маршруты строит OSRM на сервере, адреса ищет Photon, а Nominatim определяет адрес по координатам. Ключ и SDK Яндекса не нужны. Имя этого документа сохранено, чтобы старые ссылки продолжали работать.

## Настройка карты

В `mobile/.env` укажите API. Векторный стиль уже включён в приложение; при необходимости можно задать собственный URL MapLibre-стиля и резервные растровые тайлы:

```env
EXPO_PUBLIC_API_URL=https://your-api.example/api
EXPO_PUBLIC_MAP_STYLE_URL=https://your-tiles.example/styles/taxi/style.json
EXPO_PUBLIC_OSM_LABELS_TILEJSON_URL=https://your-tiles.example/shortbread/tilejson.json
EXPO_PUBLIC_OSM_TILE_URL=https://your-tiles.example/{z}/{x}/{y}.png
```

`EXPO_PUBLIC_MAP_STYLE_URL` необязателен: пустое значение использует встроенный стиль на публичных векторных тайлах OpenFreeMap. `EXPO_PUBLIC_OSM_LABELS_TILEJSON_URL` задаёт отдельный источник свежих адресных подписей; по умолчанию используется Shortbread OSMF. `EXPO_PUBLIC_OSM_TILE_URL` применяется только как запасная подложка при ошибке векторной карты; пустое значение использует `tile.openstreetmap.org`. Expo включает значения в приложение при сборке; изменения переменных Railway не меняют уже установленный APK. После смены мобильной конфигурации нужна новая сборка. В GitHub Actions URL стиля, подписей и резервных тайлов задаются переменными репозитория `EXPO_PUBLIC_MAP_STYLE_URL`, `EXPO_PUBLIC_OSM_LABELS_TILEJSON_URL` и `EXPO_PUBLIC_OSM_TILE_URL`, API — `EXPO_PUBLIC_API_URL`.

Векторные данные и шрифты по умолчанию загружаются с OpenFreeMap, который разрешает использование в мобильных и коммерческих приложениях без ключа, но не предоставляет SLA. Базовый стиль адаптирован из OpenFreeMap Bright: изменены цвета земли, дорог, зданий, воды, зелёных зон и правила выбора языка подписей. [Лицензии исходного стиля](../mobile/src/native/openfreemap-style-LICENSE.md) сохранены рядом с его JSON; карта показывает ссылки на стиль OpenMapTiles Bright и данные OpenStreetMap. Для гарантированной доступности используйте собственный сервер или поставщика с договором. Публичные сервисы OSMF имеют ограниченные ресурсы; для постоянной массовой нагрузки настройте собственный источник Shortbread и резервных тайлов. Не выполняйте предварительную загрузку публичных тайлов. [OpenFreeMap](https://openfreemap.org/quick_start/), [политика векторных тайлов OSMF](https://operations.osmfoundation.org/policies/vector/), [политика растровых тайлов OSM](https://operations.osmfoundation.org/policies/tiles/), [атрибуция данных](https://www.openstreetmap.org/copyright).

OpenFreeMap публикует новые векторные тайлы планеты примерно раз в неделю. Приложение запрашивает актуальный TileJSON по адресу `/planet`, поэтому после публикации новой версии данные обновятся без пересборки APK, но самые последние правки в OSM до этого момента не появятся. Точную версию можно увидеть в поле `tiles` ответа `https://tiles.openfreemap.org/planet` (на 13 сентября 2026 года — `20260906_080001_pt`). Если городу нужны более частые обновления, подготовьте собственные векторные тайлы из свежего OSM-экстракта или подключите поставщика с нужной частотой; оформленный стиль нужно сохранить поверх нового источника той же схемы OpenMapTiles. Слой `building` в этой схеме не содержит названий: номера адресов берутся из `housenumber`, названия парков из `park`, а организаций и объектов — из `poi`.

Shortbread перекрывает устаревшие подписи улиц базового стиля и от масштаба 13 показывает служебные дороги, полевые пути, пешеходные/велодорожки и ступени; от масштаба 14 — контуры зданий и дорожные площади. При меньшем масштабе эти детали отсутствуют в самих тайлах. Shortbread не гарантированно новее OpenFreeMap в каждом районе: оба источника публикуют и кэшируют тайлы независимо, а OSMF требует учитывать сроки кэширования и не даёт SLA. Если дом не нанесён в OSM или отфильтрован поставщиком тайлов, стиль приложения не сможет его добавить; для полного контроля над составом и частотой обновления нужен собственный векторный источник с нужной схемой и более высоким максимальным масштабом. При смене языка приложения поиск Photon и обратное геокодирование Nominatim получают `ru` или `ky`; если перевод конкретного объекта отсутствует в индексе, используется доступное имя. Голос манёвров тоже выбирается по языку приложения. Само название дороги в шаге маршрута приходит из сохранённого графа OSRM: оно не переводится запросом `steps=true` и обновится лишь после безопасной пересборки графа из свежего OSM-снимка. Для гарантированной кыргызской озвучки нужен установленный на устройстве кыргызский голос TTS.

## Сервер маршрутов и адресов

Параметры серверных сервисов находятся в `server/.env.example`. Конфигурация для собственных экземпляров:

```env
ROUTING_PROVIDER=osrm
OSRM_BASE_URL=https://your-routing.example
NOMINATIM_BASE_URL=https://your-geocoding.example
PHOTON_BASE_URL=https://your-address-search.example
NOMINATIM_USER_AGENT=TaxiGO/1.0 (contact: your-contact@example.com)
NOMINATIM_MIN_INTERVAL_MS=1000
```

Укажите корневые адреса сервисов без `/route/v1`, `/search` и `/reverse`, а также действующий контакт владельца сервиса. В Railway эти значения задаются у API; для Docker и локального сервера — в `server/.env`.

Для размещения собственных OSRM и Nominatim на данных Кыргызстана подготовлены `docker-compose.maps.yml` и [пошаговая инструкция](../server/MAPS.md). Они описывают загрузку выгрузки, импорт данных, постоянные тома и запуск сервисов. Для этого варианта в корневом `.env` задаётся отдельный пароль Nominatim; адреса готовых сервисов прописываются в `server/.env`.

OSRM должен быть подготовлен с автомобильным профилем и актуальной выгрузкой OSM для всей зоны обслуживания. Он возвращает дорожную геометрию, расстояние, расчётное время и последовательность манёвров. Сервер использует дорожный маршрут и при расчёте цены: сумма по-прежнему определяется тарифом на сервере. Для навигации используются шаги `steps=true` и полная геометрия GeoJSON. [OSRM Route API](https://project-osrm.org/docs/v5.24.0/api/#route-service).

В development OSRM по умолчанию использует демонстрационный `router.project-osrm.org`; он не гарантирует обслуживание рабочего приложения. В production сервер требует настроенный отдельный OSRM и отклоняет демонстрационный адрес. При недоступности дорожного сервиса показывается ошибка: приблизительный маршрут по прямой не выдаётся за дорогу.

Для обратного геокодирования настройте собственный Nominatim или совместимого поставщика, разрешающего ваш сценарий и нагрузку. Значение `NOMINATIM_BASE_URL` по умолчанию пустое; в production конфигурация без него не запускается. Сервер отправляет идентифицирующий User-Agent, последовательно выполняет запросы Nominatim с заданным интервалом и кеширует результаты.

Для быстрого поиска по мере ввода в Railway развёрнут отдельный Photon 1.3.0 с данными Кыргызстана и названиями на русском, кыргызском и английском. `PHOTON_BASE_URL` указывает на его корневой адрес; установка описана в [deploy/README.md](../deploy/README.md). Запросы Photon не стоят в секундной очереди Nominatim. Поиск автоматически запускается после паузы ввода 250 мс, начиная с двух символов; устаревшие запросы отменяются. Photon поддерживает неполный ввод и опечатки. Найденные рядом улицы имеют приоритет над одноимёнными в других городах; явный поиск города остаётся общим по Кыргызстану. Результаты кешируются, одинаковые одновременные запросы объединяются. Если номер дома отсутствует в данных, может возвращаться улица без неподтверждённого номера. При пустом `PHOTON_BASE_URL` сохраняется прежний текстовый поиск через Nominatim; при ошибке настроенного Photon API возвращает ошибку доступности.

Общедоступный `nominatim.openstreetmap.org` в конфигурации запрещён: его политика запрещает автодополнение и использование транспортными трекерами, ограничивает совокупную нагрузку приложения одним запросом в секунду и требует идентификации, кеширования и возможности смены сервиса. [Политика Nominatim](https://operations.osmfoundation.org/policies/nominatim/), [установка Nominatim](https://nominatim.org/release-docs/latest/admin/Installation/).

## Сборка двух приложений

Используется `@maplibre/maplibre-react-native` 10.4.2, Expo SDK 54 и `newArchEnabled: false`. Плагин MapLibre уже подключён в `mobile/app.config.ts`; его Android-зависимости доступны в Maven Central. `expo-speech` обеспечивает синтез русской речи, `expo-keep-awake` удерживает экран включённым при активной навигации. MapLibre отсутствует в Expo Go, поэтому необходима новая нативная сборка. [Установка MapLibre для Expo](https://maplibre.org/maplibre-react-native/docs/setup/expo/).

```powershell
npm --prefix mobile ci
cd mobile
npm run prebuild:client -- --platform android --no-install
npm run android:client
npm run prebuild:driver -- --platform android --no-install
npm run android:driver
```

На macOS замените `android` на `ios` в командах платформы и запуска. Идентификаторы приложений и отдельные EAS/Firebase-настройки приведены в [APP-VARIANTS.md](APP-VARIANTS.md). Старые APK продолжают использовать прежний код до переустановки новой сборки.

## Как работает навигация

После принятия заказа водитель строит путь от текущей GPS-позиции к месту подачи. После начала поездки целью становится адрес назначения. Карта показывает собственное положение, линию дороги и ближайший манёвр; камера может следовать за водителем. При уходе с маршрута запрашивается новый маршрут.

Русские подсказки формируются из манёвров OSRM и расстояния до них: например, «Через 100 метров поверните направо». Повтор одного этапа подсказки подавляется, голос можно отключить. Для озвучки нужен доступный русский голос системного синтезатора речи. Голосовые данные можно установить в настройках телефона; их наличие и поведение звука проверяются на устройстве. Прежние записи «Новый заказ», сообщения пассажира и завершения поездки сохраняются отдельно; см. [DRIVER-SOUNDS.md](DRIVER-SOUNDS.md).

В водительском приложении фоновая навигация и передача координат доступны для активного назначенного заказа после включения геолокации «Всегда». Android запускает foreground service с постоянным уведомлением; обработчик Expo TaskManager отправляет только свежий GPS и озвучивает манёвры в фоне. После завершения, отмены, снятия водителя или выхода из аккаунта передача прекращается. Принудительная остановка приложения системой/пользователем прекращает фоновую работу. Клиентское приложение не запрашивает фоновую геолокацию.

Клиент получает положение только назначенного ему водителя в статусах ASSIGNED, ARRIVED и IN_PROGRESS. После 30 секунд без свежего сигнала метка скрывается. При движении к клиенту показан путь до подачи; остальные водители недоступны. До принятия предложения водитель также видит свой путь и расстояние по дороге до клиента. Реализация и проверка — [DRIVER-TRACKING.md](DRIVER-TRACKING.md).

OSRM сам по себе не предоставляет текущие пробки, ограничения скорости, предупреждения о камерах или офлайн-навигацию. Время в пути является расчётным; качество маршрута и найденных адресов зависит от полноты OSM и обновления серверных данных.

## Проверка

```powershell
npm --prefix server test
npm --prefix mobile run typecheck
npm --prefix mobile run test:native
npm --prefix mobile run test:navigation
```

Перед выпуском проверьте оба приложения на обслуживаемых улицах: поиск адреса и выбор точки, дорожный маршрут, право доступа к GPS, указатель собственного положения, смену цели после старта поездки, уход с маршрута, отсутствие сети, отключение голоса, фон и возврат в приложение. Отдельно проверьте слышимость русских подсказок на Android и iOS, включая подключение к автомобильной аудиосистеме. Автоматические тесты не подтверждают качество GPS и синтезатора на физическом телефоне. Предыдущие записи о MapKit в отчётах проверки относятся к старым сборкам.
