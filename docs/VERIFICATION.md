## Текущая версия: карта только A → B

После уточнения требований удалены фоновая геолокация водителя, передача его координат, серверный endpoint местоположения, Socket.IO-событие координат, ETA подачи и маркер движущейся машины. Заказы получают подтверждённые свободные водители на линии без определения расстояния до них. MapKit используется только для поиска/выбора точек и показа маршрута A → B.

В базу добавлена миграция `202609050002_remove_driver_tracking`, удаляющая таблицу `DriverLocation`. Она применена к локальной и тестовой базам.

## Условия бесплатного MapKit

Актуальные публичные условия Яндекса разрешают маршрутизацию внутри Mobile SDK MapKit и устанавливают лимит бесплатной версии до 1 000 пользователей карты в сутки. Приложение должно быть открыто доступно бесплатно, сохранять атрибуцию и кнопку «Открыть в Картах». Мониторинг транспорта и диспетчеризация на основе данных Яндекса запрещены в бесплатном сценарии, поэтому эта функциональность удалена. Подробности и ссылки на первичные источники — в [MAPKIT.md](MAPKIT.md).

## Требует отдельной приёмки

| Проверка | Что необходимо |
|---|---|
| Реальная карта, поиск и маршрут A → B | Бесплатный ключ Mobile SDK MapKit, ограниченный `kg.taxigo.app` |
| Сборка и запуск iOS | Mac, Xcode и CocoaPods; подготовлена `.github/workflows/native.yml` |
| Настоящие SMS | Настроенный SMS-шлюз |
| Push при закрытом приложении | APNs/FCM и провайдер push, физические устройства |
| Полная поездка на двух устройствах | Два телефона и доступный по сети API |

Сервер по умолчанию фиксирует цену по приблизительной дистанции (`ROUTING_PROVIDER=approximation`), поэтому отдельный серверный ключ Яндекса не требуется. Если бизнесу понадобится точная серверная тарификация по дорожному маршруту, Router API подключается отдельно.

## Сценарий приёмки на устройствах

1. Установить приложение на два устройства, войти клиентом и подтверждённым водителем; водитель выходит на линию без запроса GPS.
2. Клиент выбирает A/B, видит маршрут MapKit, получает цену и создаёт заказ.
3. Водитель получает предложение без своей позиции и расстояния до клиента, принимает его и проходит «Приехал → Начать → Завершить».
4. Проверить звонок, чат и «Я выхожу»: статус должен остаться `ARRIVED`.
5. Отключить и восстановить сеть, перезапустить клиентское приложение: активный заказ должен восстановиться.
6. Повторить завершение: должна остаться одна комиссия, наличный доход учитывается отдельно; клиент ставит оценку.
7. Проверить отмены, возврат в поиск, пропуск, таймаут и одновременное принятие двумя водителями.
8. Проверить, что ОС не предлагает фоновое разрешение геолокации и приложение не показывает движущиеся машины.

## Клиентский сценарий по новым референсам — 6 сентября 2026

Клиентский главный экран переделан под большую карту с плавающими кнопками и белой нижней панелью.
