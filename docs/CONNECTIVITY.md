# Подключение приложения к серверу

## Текущее обновление доставки и панели

Ошибка `Cannot GET /api/food/orders/history` на экране «Мои заказы еды» означала, что прежнее развёртывание API не содержало маршрута доставки. Каталог ресторанов и блюд зависел от отсутствовавшего `/api/food/catalog`. Колокольчик общего главного экрана также открывает историю заказов еды, поэтому там отображалась та же ошибка; это не сообщение об отсутствии разрешения на push.

В текущую серверную сборку включены каталог, заказы еды, баннеры, фотографии и административные маршруты. Мобильный интерфейс получает до трёх активных баннеров с сервера и обновляет каталог и статусы по событиям. Вместо технического `Cannot GET` при недоступном разделе показывается понятное сообщение с повторной попыткой.

**Обновлённый API опубликован в Railway:** развёртывание `46d10e0f-dda8-440a-9404-30d1b100b40f`, статус `SUCCESS`. Панель опубликована в приватном режиме Sites, версия 1. Через публичный API подтверждены разрешённый CORS для адреса панели и событие `admin:changed` при изменении баннера. Локально миграции, сборка и 50 серверных тестов прошли. Адрес панели, вход владельца и резервная копия — в [ADMIN.md](ADMIN.md). SMS остаётся development, четыре ресторана из референсов помечены как демонстрационные.

После развёртывания прошли 25 проверок публичного сервера: история такси и еды, активный заказ еды и чтение всех разделов панели работают; вход и права администратора проверяются, отрицательные тарифы отклоняются. Соединение событий установлено для администратора и клиента, обращения с адреса панели разрешены.

Актуальный APK для телефона: [Taxi-GO-android-arm64.apk](../artifacts/Taxi-GO-android-arm64.apk), ARM64, публичный API `https://api-production-3839.up.railway.app/api`. Размер — **84 475 438 байт**, SHA-256 — `9B5CFA6652F314476CD0DF96805089D47A08953BF38D9F3CB1C39A4E5A1F3AD5`. Размер и контрольная сумма проверены у итогового файла. Прежняя синяя авторизация и зелёные ячейки SMS-кода сохранены.

На главной включён один управляемый баннер с исходным `home-promo`, ведущий в Sushi Roll; всего можно включить до трёх. Данные меню и фотографии управляются через панель. Проверки ниже относятся к предыдущей сборке; их контрольная сумма не относится к актуальному APK. Проверка публикации с компьютера не подтверждает доступ через конкретную мобильную сеть, VPN или DNS телефона.

## Предыдущая проверка APK для телефона

В выданном `Taxi-GO-auth-local.apk` был встроен адрес `http://10.0.2.2:3000/api`, предназначенный для Android Emulator. На физическом телефоне эта сборка не может подключиться к серверу разработчика.

Для телефона подготовлена отдельная сборка [Taxi-GO-android-arm64.apk](../artifacts/Taxi-GO-android-arm64.apk) с `APP_ENV=production` и публичным HTTPS API `https://api-production-3839.up.railway.app/api`. Прежний дизайн авторизации и зелёные ячейки кода сохранены. Сборку следует устанавливать поверх предыдущей версии приложения.

Android release-сборка прошла. Внутри APK проверены наличие публичного API, отсутствие локального адреса эмулятора, архитектура ARM64 и подпись. Исходники экранов авторизации в комплекте совпадают с текущими файлами проекта. SHA-256: `9B83E9A1C032221F1D84E69BC2D41BD4DF759EFC88F614CCDF6A7AC82E8A5284`.

Повторная проверка публичного API через настоящий мобильный модуль прошла запрос тестового кода, вход, чтение профиля и тарифов, подключение WebSocket, обновление сессии и выход. Тестовая сессия отозвана; реальные SMS не отправлялись. Все 12 проверок сетевого модуля прошли. Физический телефон к компьютеру не подключён, поэтому его конкретная сеть не проверялась.

В момент этой предыдущей проверки публичный сервер ещё не содержал `/food/catalog` (HTTP 404). Маршруты доставки теперь включены в обновление API; текущий статус его публикации указан выше.

## Что установлено

- Демонстрационный API `https://api-production-3839.up.railway.app/api` доступен с компьютера: `/health`, `/config` и `/tariffs` отвечают HTTP 200. Railway показывает запущенное развёртывание со статусом SUCCESS.
- Проверка через настоящий модуль мобильного API прошла запрос development-кода, вход, чтение профиля клиента и тарифов, WebSocket, обновление токенов и выход. Созданная для проверки сессия отозвана. Настроенный development SMS-провайдер не отправляет реальных сообщений.
- В исходном `artifacts/Taxi-GO-android-arm64.apk`, собранном 6 сентября в 00:46 по локальному времени, таблица строк Hermes содержит адрес Railway. Этот APK не направлял запросы на localhost.
- Без подключённого телефона точную причину наблюдавшейся на нём ошибки воспроизвести не удалось. Проверка с компьютера не подтверждает доступность сервера через конкретную мобильную сеть, VPN или DNS телефона.

## Исправления

- В сборках GitHub Actions заменён неработающий адрес-заглушка `taxi.example.com` на Railway с возможностью переопределения через переменную репозитория `EXPO_PUBLIC_API_URL`.
- При отсутствии локального `.env` мобильное приложение использует Railway. Ранее оно обращалось к `localhost`, то есть к самому телефону.
- URL проходит общую нормализацию для приложения и конфигурации сборки; у адреса без пути автоматически добавляется `/api`. Production-сборка отклоняет URL-заглушки, HTTP и адреса localhost/Android Emulator.
- Таймаут запроса, повреждённый ответ и отсутствие подключения имеют разные сообщения. Ответ сервера с ошибкой, например ограничение запросов кода, сохраняет свой текст и не объявляется потерей сети.
- Сетевые проверки покрывают адрес без `.env`, нормализацию и совместимость с URL в React Native, неверную production-конфигурацию, ответы 429, повреждённый JSON и таймаут с сохранением сессии. Сохраняются проверки обновления токенов и защиты от подмены сессии: всего 12 тестов API.

## Как проверить подключение

Откройте на том же телефоне и через ту же сеть [проверку сервера](https://api-production-3839.up.railway.app/api/health). Ожидаемый ответ: `{"status":"ok"}`. Если страница не открывается, проверьте доступ через другую сеть и настройки VPN/DNS. Если открывается, убедитесь, что установлен последний APK: адрес сервера встроен при сборке, поэтому редактирование `.env` не обновляет старую установку.

Для локального API на Android Emulator нужен адрес `http://10.0.2.2:3000/api`, на физическом телефоне — LAN-адрес компьютера и работающий сервер. `localhost` на телефоне не является компьютером разработчика. Локальная HTTP-конфигурация предназначена для `APP_ENV=development`.
