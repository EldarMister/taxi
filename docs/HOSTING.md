# Независимые сервисы сайта и приложения

Сайт и админка работают в сервисе `website`. NestJS API работает отдельно в `api`: обслуживает приложения, авторизацию, данные и события между сервисами. У сайта нет доступа к PostgreSQL или секретам сервера; он передаёт REST и Socket.IO запросы API по закрытой сети Railway.

| Адрес | Назначение |
| --- | --- |
| https://atlas-app.up.railway.app/ | Сайт Atlas |
| https://atlas-app.up.railway.app/admin/ | Панель управления |
| https://api-production-47be.up.railway.app/api/ | Сохранённый API установленных приложений |

## Railway

Исходники сайта, админки и их сборка находятся в `web/`; админка — `web/admin/dist`. Изменения `/web/**` автоматически разворачиваются из GitHub.

Оба сервиса находятся в переданном проекте `taxi-go`, workspace **eldarmister's Projects**.

- `api`: корень репозитория, `Dockerfile.railway`, `PORT=8080`, готовность `/api/health`. Образ содержит только сервер, Prisma и служебные данные. Существующие переменные базы, геосервисов и авторизации сохраняются. `PUBLIC_SITE_URL` задаёт новый адрес сайта для перенаправления старых публичных ссылок.
- `website`: GitHub `EldarMister/taxi`, ветка `codex/driver-road-signs`, корень `/web`, `Dockerfile`, `PORT=8080`, готовность `/healthz`. Образ содержит сайт, админку и публичные APK. `API_UPSTREAM=api.railway.internal:8080`. Nginx обновляет приватный адрес API через DNS и поддерживает WebSocket Upgrade.
- Для Dockerfile явно задаётся `RAILWAY_DOCKERFILE_PATH`. Эти сервисы можно выпускать независимо: изменения сайта не требуют пересборки API.
- Адрес сайта добавляется в `CORS_ORIGINS` API с сохранением прежних разрешённых адресов. Установленные приложения продолжают обращаться к прежнему API.
- Свой домен подключается к **website**, а не к **api**. После подключения нужно обновить `PUBLIC_SITE_URL`, `CORS_ORIGINS` и публичный источник APK.

Railway поддерживает [Dockerfile](https://docs.railway.com/builds/dockerfiles) и [приватную связь сервисов](https://docs.railway.com/networking/private-networking). Поддержка событий настроена по [схеме проксирования WebSocket Nginx](https://nginx.org/en/docs/http/websocket.html).

## Docker на другом хостинге

Корневой `docker-compose.yml` запускает PostgreSQL, API и сайт отдельно. Для сайта используется `web/Dockerfile`, `API_UPSTREAM=server:3000`, порт 8080. Настройки API берутся из `server/.env`. Перед внешними адресами нужен HTTPS; порт PostgreSQL остаётся закрытым для внешней сети. Перед миграциями сохраняется резервная копия базы.

## Вход и устойчивость

- Данные владельца сохранены в `.local/admin-access.txt`. Этот файл исключён из Git и Docker. Пароль не входит в файлы сайта. В базе хранится scrypt-хеш.
- Каждый телефон или компьютер получает отдельную серверную сессию. Права администратора проверяются API для каждого защищённого действия.
- «Запомнить вход» сохраняет вход в выбранном браузере. При запрете хранилища вход работает до закрытия или перезагрузки страницы.
- В современных браузерах с Web Locks обновление сохранённого входа согласовано между вкладками. Выход распространяется на вкладки с тем же сохранённым входом. Для старых браузеров без Web Locks используйте одну вкладку панели.
- После возвращения сети или открытия вкладки панель восстанавливает авторизацию соединения. При отсутствии событий она запрашивает актуальные данные каждые 30 секунд, пока вкладка видима. Временный сетевой сбой не стирает вход.
- Файлы админки отдаются без кеширования, чтобы после обновления не смешивались старые и новые модули. Панель исключена из индексации и имеет ограничения безопасности браузера; защиту данных обеспечивает авторизация API.

Для рабочего запуска нужны резервные копии PostgreSQL с проверкой восстановления, мониторинг `/api/health` и настройка настоящих SMS/push-провайдеров. Текущую development-конфигурацию API нельзя считать готовой к массовому запуску. Не включайте несколько экземпляров API без отдельной настройки общей доставки событий Socket.IO.

## APK и ссылки магазина

В сервис сайта входят подготовленные публичные APK из `web/public/downloads` могут входить в Docker-сборку. `prepare-downloads.mjs` выбирает актуальный выпуск, включая имена с суффиксом `-arm64`, записывает размер и SHA-256. В сборке без папки `mobile` уже подготовленные файлы сохраняются только при совпадении размера и контрольной суммы.

Только для сборки сайта при ограничении загрузки большого архива используются `ATLAS_RELEASE_DOWNLOAD_BASE` и `ATLAS_RELEASE_VERSION`: во время сборки APK получаются с действующего сайта, проверяются по версии, размеру и SHA-256 и включаются в готовый образ. При несовпадении сборка останавливается. После запуска контейнер не скачивает файлы и не зависит от временного доступа по SSH. Для первого размещения файлы должны быть предварительно опубликованы на источнике.

Вместо встроенных APK можно задать публичные ссылки `VITE_CLIENT_APK_URL` и `VITE_DRIVER_APK_URL`; доступны также четыре `VITE_*_APP_STORE_URL` / `VITE_*_GOOGLE_PLAY_URL` из `web/.env.example`. Это публичные параметры сборки. Без APK или ссылок кнопки скачивания остаются недоступными. Закрытые файлы, ключи, резервные копии и `.env` в выпуск не входят.

## Проверка перед публикацией

Из корня проекта:

```powershell
npm run build:web
npm --prefix server run build
npm run test:hosting
```

Тесты проверяют перенаправление старых публичных ссылок в отдельный сайт, сохранение ответов API и сессии нескольких вкладок. Они не заменяют проверку DNS, HTTPS, реальных устройств, WebSocket и резервных копий после публикации.

Локальная проверка 8 октября 2026: сборки сайта и сервера прошли; 7 тестов размещения/сессий и 6 тестов защиты админки прошли. В браузере проверены главная страница и форма входа в областях шириной 360, 768 и 1280 px; устранено обрезание формы на узком экране. Сохранённый вход проверен на действующем API, тестовая сессия завершена. Docker-контейнер, настоящий телефон и подключение нового домена в этой проверке не запускались; публикация подготовленных изменений не выполнялась.
