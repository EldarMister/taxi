# Локальная проверка отката

> Актуальное продолжение: [SECURITY-RAILWAY.md](SECURITY-RAILWAY.md). Этот документ сохраняет доказательства прежнего локального этапа. Последующие проверки на Railway DEV, подтверждённое происхождение API-кода и оставшиеся блокировки описаны отдельно; локальные результаты не доказывают production готовность.

Проверка выполнена 13 октября 2026 года. Production, Railway и внешние провайдеры не использовались.

## Источник и окружение

Реконструированный предыдущий кандидат взят из локального `order-cancellation-api-release`. Его 64 исходных файла, конфигурация компилятора и схема скопированы без `.env` в игнорируемый `.local/prior-candidate/server`; SHA-256 сохранены в `provenance.json`. Исходный каталог не изменялся.

Предыдущий сервер скомпилирован с текущими локальными зависимостями. Для него отдельно сгенерирован Prisma Client из предыдущей схемы, без нового `OrderEventOutbox` и поля `browserSession`. Изменён только путь вывода генератора. Исторический контейнер, его зависимости и digest не воспроизведены; соответствие production не подтверждено.

Старый и новый Nest-серверы работали с одной синтетической PostgreSQL 18 на точном разрешённом loopback-адресе. Новое меню записано через настоящий ресторанный HTTP API нового сервера. Затем предыдущий сервер выполнял реальные HTTP-чтения и записи. Фоновые обработчики отключены в испытании, все тестовые данные удалены после завершения. Загрузка `.env` заблокирована; URL геопровайдеров заменены на loopback.

## Результаты

| Проверка | Статус и доказательство |
|---|---|
| Совместимость прежней схемы с новой | Проверено: прежние модели и поля сохранены; старый Prisma Client читает и записывает данные в расширенную схему. |
| Новые цены и обязательные модификаторы | Проверено: старый кандидат читает созданный новым сервером заказ; новый заказ из старого API стоит 230 сом, обязательная опция проверяется. |
| Outbox при записи старым сервером | Проверено: новый SQL-триггер создаёт запись outbox после записи старым Prisma Client. |
| Прежний вход админки | Проверено: парольный Bearer-вход работает; обычный клиент не получает административный доступ и не может изменить роль. |
| Разделение legacy/v2 каталога | Подтверждена блокировка: прежний сервер выдаёт v2-блюдо старому клиенту, хотя новый legacy-каталог скрывает его. |
| Новая админка с cookie | Подтверждена блокировка: прежний сервер отвечает 404 на browser-login; новую админку нельзя оставить при таком откате. |
| Изоляция browser/mobile сессий | Подтверждена блокировка: прежний `/auth/refresh` принимает действующий browser refresh secret и выдаёт mobile admin token. Новый сервер отклоняет его с 401, сохраняя browser-семейство. |
| Буквальный `main` с новыми данными | Подтверждена блокировка отдельным исполняемым сравнением: цена 260 вместо 230 сом, отсутствие обязательной опции принимается. |

## Условия выпуска

**Проверка не подтверждает безопасный откат на `main` или на реконструированный предыдущий кандидат.** Нужен проверенный совместимый образ отката, сохраняющий исправления безопасности, разделение каталога и изоляцию типов сессий. Сервер и админку необходимо проверять как согласованную пару.

Неизвестное происхождение production остаётся самостоятельной блокировкой выпуска. Локальная совместимость ORM и цен не доказывает совместимость установленного приложения, фактических доменов и исторического контейнера. Изменение production или отзыв его сессий требуют отдельного согласования.

Повтор локального испытания после подготовки игнорируемого предыдущего кандидата:

```powershell
node .local/security-audit/run.cjs ../.local/security-audit/rollback-probe.cjs
```

Результат: `.local/security-audit/rollback-result.json`. Испытание завершается успешно только для проверяемых совместимых операций; отрицательные признаки отката записываются явно и остаются блокировками.
