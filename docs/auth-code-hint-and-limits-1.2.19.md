# Вход: тестовая подсказка и лимиты запросов — Atlas 1.2.19

«Слишком много запросов. Попробуйте позже» — ответ 429 при превышении лимита запросов кода. Для номера разрешены один запрос в минуту и пять в час, для IP — двадцать в час. Лимиты сохранены. После отказа приложение теперь показывает оставшееся время и блокирует повторное нажатие для этого номера до окончания ожидания.

## Исправления

Подсказка с тестовым кодом показывается только если сервер подтвердил конкретный номер из своей тестовой настройки. Ответ должен одновременно содержать `development: true`, `channel: development`, `testPhone`, точно совпадающий с запрошенным номером, и шестизначный код. Одного общего признака development больше недостаточно. Ответы обычного SMS-провайдера, старые неподтверждённые ответы и ответы для другого номера не показывают ни код, ни текст «Тестовый вход». Переход с тестового номера на обычный убирает подсказку.

`testPhone` добавляется сервером только для разрешённых тестовых номеров. Обычные номера по-прежнему получают код через настроенного провайдера. Список из трёх тестовых номеров, провайдер Nikita и запрет тестового входа для удалённых пользователей/администраторов сохранены.

Прежняя последовательность проверок увеличивала часовые счётчики перед отказом минутного счётчика. Повторные нажатия в течение минуты могли израсходовать часовой лимит без новых отправок. Теперь три ограничения запроса кода резервируются в одной транзакции: при отказе изменения счётчиков откатываются. Принятый запрос, включая попытку доставки провайдером, остаётся учтённым. Автоматических повторов отправки SMS нет.

Сроки окон и время ожидания рассчитываются самой базой в UTC. Проверка на локальном PostgreSQL с часовым поясом, отличным от UTC, обнаружила прежнюю зависимость сырых запросов от часового пояса; она исправлена. Ответ 429 содержит положительное целое `retryAfterSeconds`, которое приложение использует для обратного отсчёта. Уже существующие действующие ограничения не сбрасываются.

Сервер также использовал адрес сокета прокси для ограничений авторизации. Без настройки прокси Express берёт адрес непосредственно подключённого узла; это могло объединять пользователей за Railway в один счётчик. Это поведение описано в [Express behind proxies](https://expressjs.com/en/guide/behind-proxies/). Railway документирует `X-Real-IP` как адрес клиента в публичном HTTP-входе: [Specs & Limits](https://docs.railway.com/networking/public-networking/specs-and-limits).

Для публичного домена этого сервиса авторизация теперь использует корректный IP из `X-Real-IP`. Проверяются совпадение с `RAILWAY_PUBLIC_DOMAIN`, наличие `X-Railway-Edge`, HTTPS и формат IP. Для локальных, приватных хостов, отсутствующих/некорректных заголовков остаётся адрес сокета. Общий `trust proxy` для всех запросов не включён. Исправление применяется к запросу/проверке кода, опросу доставки и обновлению сессии.

## Проверки

- 53 проверки мобильного экрана входа и API прошли, включая обычные/тестовые номера, несовпадающий номер в ответе, неверный формат кода, смену номера, повторную отправку, таймер после 429, разные номера и отсутствие автоматического повтора SMS.
- 55 серверных проверок авторизации прошли, включая локальные одноразовые тестовые коды, отправку обычных номеров провайдеру, удалённых пользователей, администраторов, подтверждение IP публичного входа и отклонение неподходящих заголовков.
- 4 проверки реальной базы PostgreSQL прошли: отказ в течение минуты не расходует часовые/IP-счётчики, следующий минутный интервал разрешает запрос, шестой запрос в час отклоняется с правильным временем, одновременные запросы не создают частичных резервов, IP-ограничение сохраняется между разными номерами, истёкшее окно сбрасывается.
- Проверки TypeScript для приложения и сервера прошли.
- Реальные SMS не отправлялись, реальные коды пользователей не запрашивались. Локальная отдельная тестовая база после проверки остановлена. Вход и обратный отсчёт на физическом телефоне ещё не проверены.
