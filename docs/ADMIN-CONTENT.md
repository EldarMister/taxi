# Актуальный контент в панели управления

Панель работает на [atlas-app.up.railway.app/admin/](https://atlas-app.up.railway.app/admin/). Рестораны, меню, фотографии по ссылкам и баннеры загружаются из рабочего API. Редактирование сохраняет тот же каталог PostgreSQL, который получает приложение; опубликованные меню не берутся из отдельного набора демонстрационных данных панели.

## Фотографии приложения и панели

Для фотографии, загруженной через панель, сервер выдаёт `/api/content/media/<id>`. Такая ссылка имеет приоритет перед встроенным изображением. HTTPS-ссылка также имеет приоритет. Новая загрузка получает новый адрес, поэтому сохранённая в кеше прежняя фотография не мешает обновлению.

Если у позиции нет ссылки, приложение использует `imageKey` и встроенные фотографии. Актуальные снимки и соответствия находятся в `mobile/src/food/foodPhotography.ts`; дополнительные ресурсы — в `mobile/src/food/assets.ts`. Для карточки блюда сначала используется идентификатор блюда, затем его `imageKey`. Встроенные фотографии имеют приоритет перед прежними дополнительными ресурсами, в том числе при выборе запасного ключа.

Панель использует автоматически созданный `web/admin/dist/content-assets.js` и точные копии исходных изображений в `web/admin/dist/assets/food/`. Модуль сохраняет соответствия ключей, размеры, кадрирование и режим показа. Старые отдельные PNG из панели больше не являются источником актуального предпросмотра.

Обновление встроенных фотографий:

```powershell
npm --prefix web run sync:admin-content
node web/scripts/sync-admin-content.mjs --check
node --test web/admin/test/content-assets.test.mjs
```

Команды `web` для разработки и сборки выполняют синхронизацию автоматически. Скрипт использует только локальные файлы проекта. Если структура исходного каталога меняется и скрипт больше не может её прочитать, сборка останавливается с пояснением.

## Отдельная сборка сайта

В Railway сервис `website` собирается из каталога `web/`, без дерева мобильного приложения. В таком выпуске нужны подготовленные `content-assets.js` и `assets/food/`. Скрипт проверяет наличие и SHA-256 всех изображений из подготовленного модуля; повреждённый или неполный комплект останавливает сборку. `web/Dockerfile` включает этот комплект в этап проверки и в итоговый образ.

Для `web/admin/dist` предусмотрено исключение из общего `.gitignore`: исходники панели, созданный модуль и изображения входят в Git-выпуск. Обычная сборка сайта Vite не собирает административные JavaScript-файлы: они обслуживаются как отдельные файлы `web/admin/dist`.

## Баннеры

Баннеры хранятся в рабочем API. Публикуется цельный набор: один широкий баннер, три квадратных или пустой набор. Черновики сохраняются для последующего редактирования. Замена набора выполняется атомарно и не требует удаления старого баннера.

В клиенте 1.2.09 каталог еды показывает опубликованные баннеры с действиями «Ресторан», «Такси», «Еда» и «Без перехода». Баннер ресторана отображается, если целевой ресторан доступен в каталоге. Пустой опубликованный набор убирает рекламу; встроенные кампании больше не подставляются автоматически.

Клиент 1.2.08 показывает только баннеры ресторанов, а при пустом наборе возвращает встроенную рекламу. Для полного управления публикацией и скрытием баннеров требуется обновить клиент до 1.2.09.

При проверке результата сравнивайте сохранённый набор с экраном приложения и обновляйте данные панели после внешнего изменения. Параметры стоимости, доступности, изображений и дополнений относятся к актуальному каталогу. Уже оформленные заказы сохраняют свой снимок названий, фотографий и стоимости.
