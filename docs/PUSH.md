# Push-уведомления Taxi GO

Приложение регистрирует Expo push token и сервер отправляет его через Expo Push API. Не смешивайте этот токен с веткой `PUSH_PROVIDER=firebase`: Firebase Admin ожидает raw FCM/APNs token другого формата.

## События

| Событие | Получатель |
|---|---|
| Заказ создан | Клиент |
| Новый доступный заказ | Подходящие водители на линии |
| Водитель назначен | Клиент |
| Новое сообщение | Другой участник поездки — клиент или водитель |
| Такси приехало | Клиент |
| Клиент выходит | Водитель |
| Поездка завершена | Клиент и водитель |

Socket.IO обновляет открытое приложение сразу. Push нужен, когда приложение свёрнуто или закрыто.

## Что требуется для рабочей сборки

1. Создайте или привяжите EAS project и укажите его UUID как `EXPO_PUBLIC_EAS_PROJECT_ID` в `mobile/.env`. В GitHub Actions используется repository variable с тем же именем.
2. Положите клиентский Firebase-файл Android в `mobile/google-services.json`. Он исключён из Git. Для CI сохраните его base64-содержимое в secret `GOOGLE_SERVICES_JSON_BASE64`.
3. Настройте FCM v1 credentials проекта в Expo/EAS, иначе Expo Push Service не сможет доставить уведомление в Android-сборку.
4. На Railway задайте `PUSH_PROVIDER=expo`. `EXPO_ACCESS_TOKEN` нужен только если в Expo включена enhanced push security. Для боевого сервера также используйте `NODE_ENV=production`.
5. Пересоберите и переустановите приложение: project ID и Firebase client config встраиваются в нативную сборку.

Проверяйте доставку на двух физических устройствах: одно с ролью клиента, второе с ролью водителя. Эмулятор и открытое приложение не подтверждают доставку в фоне.

## Первый запуск

После входа приложение показывает два поясняющих экрана: геолокация, затем уведомления. Системный диалог появляется только после нажатия основной кнопки. Отказ не блокирует приложение; разрешение можно выдать позже в настройках телефона. Пройденный шаг хранится отдельно для каждого аккаунта на устройстве.
